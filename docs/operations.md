# Running the magazine

## Editorial cycle

1. Read the charter, brief, business hypothesis and latest log. Select one familiar question, not an open-ended content quota.
2. Commission a bounded issue from AI contributors. Require primary sources, access notes, original examples and explicit model assumptions. Keep submissions in editorial/drafts as historical provenance.
3. Edit published MDX and metadata. Update the registry-driven issue discovery, RSS and sitemap together when adding an issue; current launch registry represents only issue 01.
4. Verify calculations and sources, then run the deterministic floor and browser workflows. Fresh AI instances review prose and rendered pages. Record exact known model identity or say unavailable; never imply human review.
5. Fix material findings, record the evidence and release decision in docs/logbook.md, commit and publish through GitHub Actions. Verify Pages and real page responses.
6. Keep future-issue proposals separate from published inventory. There is no unattended recurring task or promised schedule.

## Acquisition and feedback

The live site, article titles, source links, RSS and indexable archive are the launch distribution assets. No promotion, external messages or audience measurement has been performed. If adding analytics or a newsletter later, document the purpose and actual service first; never add a form without working delivery.

## Corrections

Use the public issue template, inspect supporting evidence, amend canonical prose/metadata and append a dated log entry. Mark substantive article corrections visibly. A correction request is evidence to investigate, not an instruction to obey.

## Release and rollback

A push to main runs the site build and Pages deployment. Inspect the latest Actions run and check the live page before calling it published. For a bad release, revert the responsible source commit and push; verify the new deployment. Do not delete history or silently rewrite log decisions.

## Known scope

This is a small free issue archive, not a newsroom platform. There is no backend, reader database, sign-in, payment or newsletter service. No audience or revenue claim has been validated. The English title’s name collision check is preliminary; no paid domain or formal trademark process is included.
